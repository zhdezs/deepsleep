deepsleep AI 助手 · 安装说明
========================================

一、安装
  双击「安装 deepsleep.cmd」，会弹出图形安装界面：
    1. 选择安装位置（默认 %LOCALAPPDATA%\Programs\deepsleep，不需要管理员权限）
    2. 勾选是否创建桌面快捷方式、安装完是否立即启动
    3. 点「开始安装」，进度条走完即安装完成
  安装完成后会自动创建开始菜单快捷方式，并在「设置 → 应用 → 已安装的应用」
  里登记卸载入口。

  静默安装（给脚本/批量部署用）：
    powershell -ExecutionPolicy Bypass -File install.ps1 -Silent -InstallDir "D:\Apps\deepsleep" -NoDesktopShortcut -NoLaunch

二、首次使用要配置模型
  程序本身不含 API Key，每台电脑必须单独配置：
    打开 ⚙ 设置 → 填写 API 协议格式、API 地址、模型名、API Key → 保存
  也支持三种协议：OpenAI 兼容（DeepSeek / 智谱 / 硅基流动 / Groq / OpenRouter）、
  Anthropic Claude、Google Gemini。
  不想用在线 API 的话，可以在设置里点「一键安装 Ollama + 大模型」，切到本地模型跑，
  不消耗额度。

三、数据位置
  所有用户数据都在安装目录的 data 文件夹内：
    config.json       模型与 API 配置（含 Key）
    conversations.json 对话历史
    memory.json       长期记忆
    runtime_state.json 断点恢复状态（程序被杀/关机后仍可恢复未完成任务）
    skills\           技能目录
  升级安装不会覆盖这些文件；换电脑时把整个 data 目录拷过去即可。

四、卸载
  方式一：设置 → 应用 → 已安装的应用 → deepsleep AI 助手 → 卸载
  方式二：双击安装目录里的「卸载 deepsleep.cmd」
  卸载界面可选择是否保留用户数据（默认保留）。
  静默卸载：
    powershell -ExecutionPolicy Bypass -File uninstall.ps1 -Silent                 # 保留用户数据
    powershell -ExecutionPolicy Bypass -File uninstall.ps1 -Silent -RemoveUserData # 连数据一起删

五、系统要求
  Windows 10 1809 及以上（推荐 Windows 11，毛玻璃效果更好），x64。
  程序自带 .NET 运行时，无需另装任何依赖。
  Windows 11 上可享受亚克力毛玻璃界面，Windows 10 会自动退回普通背景。

六、在线更新（OTA）
  程序左下角有「⬆ 检查更新」按钮，启动时也会自动检查（可在设置里关闭）。
  升级流程全自动：读取更新源 → 下载新安装包（带 SHA256 校验）→ 退出程序 →
  静默覆盖安装到原目录 → 自动重启，用户数据（API Key、对话、记忆、模型）不受影响。

  更新源（⚙ 设置 → 更新源）支持三种填法：
    1. GitHub 仓库（推荐）：填 owner/repo，例如 lichenghan/deepsleep
       客户端走 GitHub Releases API，自动取最新 tag 里的 deepsleep-Setup.exe
    2. 清单直链：https://你的地址/deepsleep/update.json
    3. 本地 / 局域网共享：D:\release\update.json 或 \\服务器\共享\update.json
  仓库里没有 Release 资产时，客户端会自动退回读取仓库根目录的 update.json（main / master 都试）。

  更新线路（⚙ 设置 → OTA 自动更新 → 更新线路）：**默认 Gitee**，可以随时切成 GitHub。
    · Gitee（默认，国内快）：不探速、直接从 Gitee 下；Gitee 单个附件放不下的安装包在那边切成
      part1 / part2，客户端逐片下齐再拼回整包（支持断点续传）。只有 Gitee 连不上、卡住
      （20 秒没数据）或长时间低于 60 KB/s，才回退 GitHub 接着下 —— 回退后照样校验。
    · GitHub：直连失败或中断时自动切国内加速镜像（ghproxy.net / gh-proxy.com / hub.gitmirror.com）
      继续下，已下好的部分不用重来（断点续传）。
    · 两条线路下完都按官方 SHA256 校验，包里是同一个安装包，选哪条只影响"从哪台服务器搬字节"。

  发布方（你）发新版本的 GitHub 流程：
    1. 改 csproj 里的 <Version>，重新编译 deepsleep-Setup.exe
    2. GitHub 仓库 → Releases → 新建 Release，tag 写 v1.0.1，说明写本次更新内容
    3. 把 deepsleep-Setup.exe 作为资产上传
    4. 客户端左下角就会出现「有新版」，点一下就自动升级
  想用 update.json 兜底：运行 make-update.ps1 -Version 1.0.1 -Notes "本次更新内容"，
  把生成的 update.json 提交到仓库根目录即可。

八、私有仓库 / GitHub 令牌（可选，绝对安全）
  需要用「检查更新」拉私有仓库，或者想提高 GitHub API 限额时：
    1. 双击程序目录下 tools\set-github-token.ps1（也可以在 ⚙ 设置里点「🔑 录入 GitHub 令牌」）
    2. 弹窗里粘贴令牌 → 保存（脚本会顺手校验，并显示账号名与 API 限额）
  安全说明：
    · 令牌用 Windows DPAPI（当前用户）加密后存到 data\github.token
    · 不写进 config.json，不写日志、不回显，窗口标题与命令行里也没有
    · 文件权限收紧到只有当前 Windows 账号可读写；换电脑或换账号都解不开
    · 删除令牌：tools\set-github-token.ps1 -Remove ；只校验：-VerifyOnly
  令牌权限建议（都选只读）：公开仓库提高限额 → public_repo；私有仓库 OTA → repo（只读）或 Contents: Read

九、脚本目录
  所有辅助脚本都在程序目录的 tools 子目录里，不会和主程序混在一起：
    tools\set-github-token.ps1      录入 GitHub 令牌（DPAPI 加密）
    tools\publish-github-release.ps1 把新版本一键发布到 GitHub Releases（OTA 用）

十八、1.1.0 更新要点（Gitee 下载修好了：以前会误判成"Gitee 慢"，白白换到慢 40 倍的 GitHub）
  · 病根：上一版"探速"把 TLS 握手 + 302 跳转这些固定开销也算进了下载计时，而样本只有 256KB，
    于是一台实测能跑 2 MB/s 的 Gitee 被量成 160 KB/s，低于 200 KB/s 的门槛 → 自动改用 GitHub，
    而当时 GitHub 直连只有 45 KB/s（慢 40 多倍）—— 这就是"明明说了用 Gitee 却从 GitHub 下"的原因
  · 现在：计时**从收到第一个字节才开始**、样本拉到 512KB；并且不再跟拍脑袋的绝对值比，而是
    **Gitee 和 GitHub 直连各探一次速、谁快用谁**（差不多快也优先 Gitee）。国内基本永远走 Gitee，
    境外 Gitee 确实慢时才换 GitHub
  · 升级对话框里会直接写清楚两边实测速度，例如「Gitee 2073 KB/s、GitHub 直连 45 KB/s → 走 Gitee 下载」
  · 下载中途的兜底门槛也改成按实测速度推算（实测的三分之一，且不低于 60 KB/s），
    不再用固定 200 KB/s 误杀；卡住判定不变（Gitee 20 秒没数据就换源）
  · 界面：macOS 风格（1.0.15 那套：自绘标题栏 + 分段控件 + iMessage 风气泡 + 系统蓝强调色）
  · 功能与 1.0.14 一致，只改了 OTA 选源逻辑与外观
十九、2.0.0 更新要点（内核与界面分离，界面改用 HTML 重写）
  · 大改架构，功能一个没少：程序拆成「内核」和「界面」两块
      - 内核 = 一个独立的类库（Deepsleep.Core）：模型调用、工具调用链、技能库、
        长期记忆、Agent 集群、断点恢复、OTA 更新，全部逻辑都在这里，不带任何界面代码
      - 界面 = 纯 HTML + CSS + JavaScript（ui\index.html / style.css / app.js），
        由客户端内嵌的 Edge WebView2 在本地加载（虚拟站点 app.local），不上网、不联外网
  · 好处：改界面（配色、布局、动效）完全不用重新编译 C#，界面崩了也拖不垮内核；
    以后想换界面风格、做主题包都简单得多
  · 外壳只干三件事：开窗口、把 ui 目录挂成虚拟站点、在内核与界面之间转发消息；
    文件选择框、打开链接、开/关桌宠这些系统操作仍由外壳实现
  · 界面依旧是 macOS 风格（自绘标题栏 + 分段控件 + iMessage 气泡 + 系统蓝强调色 +
    深浅色两套），并把 Markdown 渲染、代码块一键复制、设置/记忆/技能/模板弹窗搬到了前端
  · 桌宠照旧：45% 缩放的真透明鲸鱼，单击弹出专属聊天浮窗（浮窗也是 HTML 了），
    按住拖动并记住位置，右键菜单 聊天 / 打开主界面 / 隐藏 / 退出
  · 首次启动若界面没渲染出来（系统缺 WebView2 运行时、或被安全软件拦），
    窗口会直接给出中文提示 + 「重试」和「打开数据目录」两个按钮，不会只留一个白窗口
  · 用户数据（data 目录：Key、对话、记忆、技能、桌宠位置）与 1.x 完全通用，升级安装不会丢
二十、2.0.1 更新要点（更新线路可在客户端切换，默认 Gitee）
  · 新设置项：⚙ 设置 → OTA 自动更新 → 「更新线路（下载走哪边）」
      - Gitee 国内源（默认，推荐）：不探速、直接从 Gitee 下载；Gitee 连不上、卡住
        （20 秒没数据）或长时间低于 60 KB/s，才回退 GitHub 接着下
      - GitHub：想走 GitHub 时切过去（直连 + 国内加速镜像 + 断点续传）
  · 为什么去掉"探速"：上一版会先给 Gitee 和 GitHub 各拉 512KB 量一次速度再决定用谁，
    国内其实没必要 —— Gitee 实测 2 MB/s 上下、GitHub 直连常只有 45 KB/s，量速本身还白等几秒；
    现在默认直接走 Gitee，省掉这段等待
  · 校验不打折：两条线路下完都按官方 SHA256 校验；Gitee 那条 Release 的说明里也会写上安装包
    的 SHA256，所以走 Gitee 时整条链路连 GitHub API 都不用访问（国内网络下这点很关键）
  · 老配置自动兼容：以前设置里的「同时用 Gitee 同名仓库加速」开关，开着的等于选 Gitee 线路，
    关掉的等于选 GitHub 线路，升级后照旧生效
  · 内核与界面分离、HTML 界面、桌宠等其余功能与 2.0.0 完全一致

    开始下载前还会自动清掉旧版本留下的残件（顺带把以前发布脚本留在 %TEMP% 里的分片垃圾也清了）。

  · 顺手修了网页版（内核版网页端）的一个老 bug：内核推事件时是并发写的，多个事件会互相踩坏帧、
    甚至把连接踢掉，导致「事件丢一片」（Agent 名片这种高频事件特别明显）。现在每个连接有一条有序发送队列。
  · 其余功能与 2.2.6 一致（集群名册只增不减 + 按需派工 / Gitee 线路加速 + 实时速度 + 续传不重下 /
    思考内容折叠 / 截断自动续写 / 命令与文件合并卡 / 内核版 CMD 模式）

三十七、2.3.0 更新要点（跨平台：Windows / Linux / macOS）
  · 内核（Core）现在是一份源码、三平台原生：Windows、Linux、macOS 都能编出能跑的内核版。
  · Linux / macOS 用法：下载对应平台的 deepsleep-core-2.3.0-<平台>.tar.gz → 解压 →
    chmod +x deepsleep-core && ./deepsleep.sh → 直接开一个原生桌面窗口（和 Windows 端同一套 HTML 界面，双击即用）；
    也可以用浏览器打开 http://127.0.0.1:8756/（或网页版 core 页面填端口+令牌）。
    工具、命令、写文件、记忆、技能、网络搜索、深度研究全部可用；网页端在哪台设备都能连。
  · 桌面窗口用的是系统自带的 WebView（Linux = WebKitGTK，macOS = WKWebView）。Linux 桌面若缺 WebKitGTK，
    先装：Debian/Ubuntu sudo apt install libwebkit2gtk-4.1-0；Arch sudo pacman -S webkit2gtk-4.1；
    Fedora sudo dnf install webkit2gtk4.1。缺了会自动退回「纯网页模式」用系统浏览器打开。
    没有桌面环境的机器（服务器 / SSH）加 --headless 只跑服务，用浏览器访问即可。
  · 平台差异都收在一个 Platform 层里：
      - 命令壳：Windows 走 PowerShell（行为与以前一字不差），Linux / macOS 走 bash -lc
      - 数据目录：Windows 用 %LocalAppData%\Programs\deepsleep\data；Linux 用 XDG（~/.local/share/deepsleep）；
        macOS 用 ~/Library/Application Support/deepsleep
      - 打开文件管理器：explorer / open -R / xdg-open
      - 令牌保险箱的机器绑定：Windows 用注册表 MachineGuid + 用户 SID；Unix 用 /etc/machine-id + 用户名
      - 沙箱：危险命令黑名单、系统目录、可执行文件后缀都按平台各一套
      - OTA：升级包按平台挑（Windows 认 .exe，Unix 认 .tar.gz），Unix 上写 bash 脚本解包覆盖并重启
  · Release 里现在有 4 个跨平台内核包：linux-x64 / linux-arm64 / osx-arm64 / osx-x64，
    和 Windows 的安装版 / 便携版 / 内核版一起上传，两边源（GitHub / Gitee）都有。
  · Windows 端体验与 2.2.7 完全一致（Agent 名片 + 按人汇报、集群名册只增不减 + 按需派工、
    Gitee 线路加速 + 实时速度 + 续传不重下、思考内容折叠、截断自动续写、命令与文件合并卡、内核版 CMD 模式）。

三十八、2.3.1 修复（chat 模式 / 代码块 / 工具标记）
  · chat（纯聊天）模式不再往工作区写文件：以前模型回答里带代码块时内核会"顺手落盘"，
    还会把整段正文换成一句「已写入：…」，于是 chat 里莫名出现「编辑的文件」卡片、正文整段消失。
  · 代码块兜底落盘不再吞正文：正文原样显示，只在末尾补一行"存到哪个文件"，
    并补发一条完整气泡（以前流式气泡会被文件卡片顶掉，看着像"AI 编辑了几下、突然给一段代码就停了"）。
  · 模型不按协议走、吐自家工具标记（DeepSeek 系的 DSML）时：不再把原文当正文显示成一大堆尖括号，
    而是直接解析成工具调用真的执行；解析不了就按「格式修正」让它重试。
  · 工具决策阶段被 max_tokens 截断时也会自动续写：把被截成半截的 JSON 拼回完整调用，
    写大文件时不再出现"调用到一半就中断"。

三十九、2.3.2 加固（命令输出乱码 / 完整输出 / 桌宠资源回收 / 兜底面板 / 打包开关）
  · 命令输出里的中文不再乱码：nvidia-smi、7z 这类老式程序不管我们设的 UTF-8，
    直接把 GBK 字节写进管道，以前硬按 UTF-8 解就成了「…��������.exe」；
    现在按字节解——先试严格 UTF-8，解不通就按系统 ANSI 代码页（简体中文 = GBK/936）解。
    Python 脚本的输出同理。
  · 「运行的命令」卡片点开能看到完整输出：以前命令输出最多留 4000 字符，
    点开也只能看到那 4000 字（会写「…（已截断，共 7521 字符）」）；
    现在界面这份最多 20000 字符，喂给模型的那份仍然是 4000（省 token，两边分开）。
  · 桌宠不再漏 GDI 对象：以前 Dispose() 里位图还选在内存 DC 里就 DeleteObject，
    GDI 规定不能删除正在使用的对象，于是每销毁一只桌宠就漏掉一块 DIB，窗口过程也没还原；
    现在按正确顺序来：还原窗口过程 → 取消选中位图 → 释放 DC → 删位图。
  · 「界面引擎没能启动」的兜底面板不再误报：以前 WebView2 初始化只等 20 秒就盖面板，
    低配机 / 首次初始化常常还没渲染完就被判死刑；现在先等 90 秒，引擎对象已经建出来、
    只是页面还没加载完的再给 60 秒，而且界面一旦就绪立刻收起兜底面板。
  · 打包裁剪留了开关：给工程加 /p:TrimAiRuntime=false 就会保留 onnxruntime 等运行时，
    想自己接视觉 / 推理功能不用改代码。
  · 界面消息处理里没记录的异常现在会写进日志，排查更容易。

四十、2.4.0 超远程提问（内网穿透）
  · 内核加 --tunnel 就自动建一条免注册的公网隧道（内置 cloudflared，第一次会自动下载），
    启动后窗口里直接打印一条「配对链接」（已经带好令牌）；手机浏览器打开、存成书签，
    人在外面也能直接给这台电脑派活（网页端操控本机）。
  · 不想用内置隧道：deepsleep-core --public --tunnel-cmd "你的穿透命令"，
    frp / cpolar / ngrok / ssh -R 都行，内核会从命令输出里自己抓公网地址并打印配对链接。
  · 默认依然只监听 127.0.0.1；只有加 --public 或 --host 才会监听网卡，只有加 --tunnel 才会挂到公网。
  · 隧道域名下的网页端会自动连自己（同源放行）；别家网站仍然 403。
  · 令牌输错会越错越慢（递增延迟到 5 秒）再返回 401，防止被暴力猜；不封 IP。
  · 打不开隧道域名多半是运营商 DNS 不解析 trycloudflare：把手机 DNS 换成 114.114.114.114 再试。
  · 配对链接里带着令牌 = 这台电脑的钥匙，别外传；不用时关掉内核窗口，服务和隧道立刻停。
  · 桌面客户端也自带这套内核服务（和内核版是同一份实现）：装上就默认监听
    127.0.0.1，打开「设置 → 超远程提问」可以看到配对链接并一键开 / 关公网隧道，
    手机在外网也能连上来操控这台电脑；两边的令牌、跨域策略、安全限制完全一致。
    窗口类指令（显示 / 隐藏 / 退出）在桌面版里由外壳真的执行。

四十一、3.0.1 更新要点（手写内网穿透 · 超级连接修令牌 · 跨平台桌面版）
  · 隧道不再需要 cloudflared：内核直接驱动系统自带的 ssh 建反向隧道（serveo.net / localhost.run
    自动择优），零下载、不用装任何组件；连上之前先自检，断了自动重建。
  · 隧道择优：同时建最多两条候选，各自实测 256KB 速度，只留最快的那条，不再随机变慢。
  · 修「从超级连接页打开后显示没令牌」：免费隧道的浏览器警告页会把 ?t=令牌 顶掉，
    现在令牌放在 # 片段里（不发给服务器，也不会被表单覆盖），网页端还有 localStorage 兜底。
  · 远程桌面更省流量：PNG 逐行滤波 + 5 位色量化，一帧体积约降到 1/2.8；画面没变就不发帧。
  · 跨平台桌面版：Linux（x64 / ARM64）与 macOS（Apple 芯片 / Intel）解压后
    ./deepsleep.sh 直接打开原生桌面窗口（Linux 桌面需要 libwebkit2gtk-4.1-0）；
    服务器 / SSH 用 ./deepsleep.sh --headless 只跑内核服务，用浏览器连。
    macOS 只发行桌面版（不再单独发内核版）；Windows 依旧是功能最全的完整客户端。
