3.2.4

版本号进位，让停在 3.2.3.0 的旧客户端也能收到这次更新。

## 工具调用改走原生（优先）

以前只能让模型自己拼一行 `{"tool_call":…}` 文本，格式错一次就得重来，参数里塞代码还容易把 JSON 撑破。现在按各家协议原生下发工具：OpenAI 兼容线路用 `tools` + `tool_calls`，Claude 用 `tool_use` 内容块，Gemini 用 `functionDeclarations`，Responses 接口用 `function_call` 条目。21 个内置工具都带上了参数 JSON Schema，模型该动手时直接发起调用，不再靠猜格式。

一轮可以发多个调用。互不依赖的活（同时读几个文件、同时搜几个方向、同时建多个文件）一次发完，客户端依次执行，再按 `tool_call_id` 把结果一起交回，不用一步一步来回磨。

老网关会自动降级：接口若明确回报「不支持 tools 参数」，记住这条线路，之后退回原来的文本 JSON 协议，不会每轮都撞一次 400。文本协议本身也补上了 `{"tool_calls":[…]}` 一次多条的写法；历史里的调用关系按 id 精确配对，重启后没有 id 的旧记录自动摊平成纯文本，避免把上一家的 id 发给另一家。

## 看图改成图片直接进请求

以前看图靠一个单独的识图模型（设置里的「图像识别」），多一道 Key、多一次转发。现在图片直接以 base64 内联进主模型的调用参数：OpenAI 兼容线路走 `image_url` 的 data URL，Claude 走 `image` 内容块，Gemini 走 `inlineData`，Responses 接口走 `input_image`。

拖动、粘贴、选择本地图片时，只要「主模型是多模态」开关打开，图片就随消息一起发给主模型，不再绕道识图工具；那条路只在主模型不吃图时作为兜底。截图看屏也一样，机器操作每一轮的界面截图都直接给主模型看，不用先转述一遍。

单张图上限 5MB（Anthropic 最紧的那条线），超过或读不到就退回纯文字，不会让整条请求失败。接口明确回报不认图片时，记住这条线路，之后直接走文字，不反复撞墙。

## 本次修复

长对话里报「接口没有返回正文」，其实不是模型的问题，是请求被本机 100 秒超时切断的。客户端以前把这种超时当成「模型没给正文」，现在等待时间交给请求自己的看门狗管：真的等不到就直说服务器繁忙，不再冒充模型的回答。

Anthropic 协议（`/v1/messages`）这条线路补齐三处：输出上限不再写死 8192，上层调大预算能生效；响应按内容块解析，思考块排在最前面也不会认错正文；拿到响应头就开始读流，长回答边生成边显示。

失败时的提示收敛了。真没拿到回复只说服务器繁忙，模型名、地址和状态码写进 `data\agent.log` 的「LLM 失败明细」；只有地址、模型名或 Key 写错（401/403/404）才提示去设置里改。

## 上下文自动压缩

长对话塞满窗口时，内核会在每次回答前估算历史用量（中文 1 字约 1 token，英文 4 字符约 1 token），超过窗口 90% 就把较早的对话折成一段摘要，写清目标、已做的事、结论和待办，最近 35% 的原文保留，切口对齐到整条用户消息。

压缩完会在会话里插一条系统消息，写明压缩前后的 token 数，用量环同步回落。压缩是确定性规则，不额外调模型。

## 思考强度

输入框的加号菜单里多了一行「思考强度」，分关、低、中、高三档。选「关」不请求推理，其余三档对应 `reasoning_effort`，OpenAI、Anthropic、Gemini 各走各的字段。设置会写进配置，重启后保持。

## 图像与视频预设

图像加了豆包 Seedream，视频加了豆包 Seedance（火山方舟）。视频提交走 `contents/generations/tasks`，查询地址模板带 `{id}`，模型名和画幅比例已经填好。原有智谱、SiliconFlow、自定义接口不变。

## 请求一律流式

所有模型调用在请求体里就是 `stream: true`。流式也是 30 秒无响应自动恢复的前提：每收到一行数据重新计时，卡住就掐掉重发，最多 3 次。

## 首启皮肤与品牌图标

内置皮肤 `openharmony-arkui` 随包分发，首次启动自动启用并切成亮色。亮色和暗色主题的 CSS 也换成了同一套设计语言。

模型名能认出品牌就用官方图标，认不出或图标缺失就用 deepsleep 自己的图标。

## Blender 连接器

Blender 改成连接器。在设置里的连接器页点「连接」，会去 `Program Files\Blender Foundation`、`LocalAppData\Programs` 和 PATH 里找 `blender.exe`，再跑一次 `blender --version` 验证，路径配错会在这一步报出来。找不到可以点「填路径」手动指定。

连上之后模型才有 Blender 工具：写 bpy 脚本后台执行（`--background --factory-startup --python`），按扩展名导出 .blend、.glb、.gltf、.obj、.stl、.fbx。没连上时工具不出现。

## GitHub 连接器

GitHub 改成设备码登录。点「用 GitHub 登录」，浏览器打开授权页，输入界面上的 8 位代码，确认即可，不用建 PAT。想用更小的权限可以点「用令牌」自己建 PAT，想用自己注册的 OAuth App 就在设置里填 Client ID（勾 Enable Device Flow）。

连上后模型多一个 GitHub 工具，能查自己的信息、列和搜仓库、列和搜以及新建 issue。令牌只存在 `data\connectors.json`，DPAPI 加 AES-256-GCM 加密，点「断开」立即从本机删除。

## 发送即路由

主会话本身就是 Router，一直活着，也一直记得上下文。每条消息先到 Router，由它决定自己回答还是按名单派活。拆出来的每一路是独立 Worker，上下文彼此隔离。

Router 和 Worker 可以分别绑定模型：路由用便宜快的，执行用能打的。每个绑定都支持接口地址、协议、模型名和 Key，Key 留空就沿用主 Key。用过的网关会进供应商档案，重启后能切回来。

## Worker 名单

在设置的扩展页里可以加角色、写备注、移除，首次启动会种一份常用名单（前端、后端、文档、调研）。同名角色复用同一个 Worker 会话，上一轮的产物和上下文都在；名单外的角色会自动加进来。移除只影响名单，历史会话保留。

## 触发器

每隔 N 分钟、每天固定时间、或者某个文件一变动，就把一句话当作用户消息交给 Router，和你手打走同一条链路。助手正在跑时这一轮跳过，不排队。剪贴板事件没做，内核要跨平台编译，不想为它引入 WinForms。

## 看门狗

启动时把上次遗留的「运行中」Worker 收成 stopped。运行中每 30 秒巡检，只收状态写着运行中、本进程没在跑、并且超过设定时间没动静的会话。时长可配，默认 10 分钟，0 表示关闭。

## 渲染与抓取

抓取网页除了正文，还会用本机 Chrome 或 Edge 无头渲染一张截图，返回图片路径。新增「渲染图片」工具，给网址或一段 HTML 就能渲染成 PNG，可以指定宽高和输出路径，产物写在 `data\render`。找不到浏览器会如实说明。

## 权限

work 模式下所有文件操作都要授权，包括读、写、打开、自动保存、生成物、装扩展、Blender 导出。允许之后这类权限在 1 小时内有效，期间同类操作不再弹窗。拆分出来的 Worker 走同一套授权，确认框回到发起它的会话。

chat 模式按能力放行：搜索、深度研究、抓取网页、渲染图片、GitHub、知识库、记忆、拆分任务都能用；读写文件、打开文件、跑命令、操作电脑、Blender 需要 work 或 boom。

## 记忆与归档

会话历史完整持久化，包含压缩前的归档，重启接着聊。「记住」只记用户画像：身份、稳定偏好、习惯、明确要求记住的事实，不再堆对话摘要。

## 其他

- 设置里保存的上下文上限以前只存不读，现在生效
- Blender 首启自动探测路径并写进配置
